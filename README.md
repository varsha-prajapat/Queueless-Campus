## 📖 Overview

Queueless-Campus is a comprehensive platform designed to modernize campus operations by eliminating physical queues and simplifying appointment booking. This application addresses the common challenges faced by students and staff, such as long waiting times, confusing appointment systems, and inefficient resource allocation. By providing a digital solution, Queueless-Campus aims to enhance user experience, optimize service delivery, and create a more organized and time-efficient campus environment.

The platform facilitates various campus services, from administrative tasks and academic consultations to facility bookings, ensuring that students and faculty can manage their time effectively and access necessary resources without unnecessary delays.

## ✨ Features

- 🎯 **Digital Queue Management**: Allow users to join virtual queues for various campus services (e.g., registrar, library, health services) from anywhere.
- ⏰ **Real-time Queue Updates**: Provide live status updates on queue positions and estimated wait times.
- 🗓️ **Appointment Scheduling**: Enable users to book appointments with staff or for specific resources (e.g., labs, study rooms) in advance.
- 🔔 **Notification System**: Send push notifications for queue turn alerts, appointment reminders, and service updates.
- 👤 **User Authentication & Roles**: Secure login for students, staff, and administrators with distinct access levels.
- 📊 **Admin Dashboard**: A comprehensive interface for staff and administrators to manage queues, appointments, services, and user data.
- 📱 **Cross-Platform Accessibility**: A modern, responsive user interface accessible on various devices.

## 🚀 Quick Start

Follow these steps to get your development environment set up.

### Prerequisites

Make sure you have the following installed:

- **Flutter SDK**: [Installation Guide](https://flutter.dev/docs/get-started/install)
- **Node.js**: v14.x or higher
- **npm** (comes with Node.js) or **yarn**
- **MongoDB**: A running instance of MongoDB or access to a MongoDB Atlas cluster.

### Installation

1.  **Clone the repository**

    ```bash
    git clone https://github.com/varsha-prajapat/Queueless-Campus.git
    cd Queueless-Campus
    ```

2.  **Backend Setup**

    Navigate to the `backend` directory, install dependencies, and set up environment variables.

    ```bash
    cd backend
    npm install # or yarn install
    ```

    Create a `.env` file in the `backend` directory by copying `.env.example`.

    ```bash
    cp .env.example .env
    ```

    **Configure your environment variables** in the `.env` file:
    <!-- TODO: List actual detected environment variables from .env.example -->

    ```
    PORT=3005
    MONGO_URI=mongodb://127.0.0.1:27017
    JWT_SECRET=your_jwt_secret_key
    # Add any other variables detected in backend config
    ```

3.  **Frontend Setup**

    Navigate to the `frontend` directory and install Flutter dependencies.

    ```bash
    cd ../frontend # Go back to root and then into frontend
    flutter pub get
    ```

    Create a `.env` file in the `frontend` directory (if used for API base URL or similar configurations).

    ```bash
    cp .env.example .env
    ```

    **Configure environment variables** in `frontend/.env`:
    <!-- TODO: List actual detected environment variables from frontend .env.example -->

    ```
    API_BASE_URL=http://localhost:3005 # Adjust if your backend runs on a different port/host
    ```

### Running the Application

1.  **Start the Backend Server**

    From the `backend` directory:

    ```bash
    npm start # or node server.js (if package.json "start" script is missing or different)
    ```

    The backend server will typically run on `http://localhost:3005` (or the port specified in your `.env` file).

2.  **Start the Frontend Application**

    From the `frontend` directory:

    ```bash
    flutter run
    ```

## 🚀 Deployment

### Production Build

#### Backend

```bash
# From the backend directory
cd backend
npm install --production # Install production dependencies
npm start # Start the backend server
```

For production, it's recommended to use a process manager like PM2 or deploy via Docker.

#### Frontend

```bash
# From the frontend directory, for web deployment
cd frontend
flutter build web
```

The build artifacts will be in the `build/web` directory, ready to be served by any static web server (e.g., Nginx, Apache, Vercel, Netlify).
For mobile, the respective build commands (`flutter build apk` / `flutter build ios`) will generate installable packages.

### Deployment Options

- **Cloud Hosting**: Deploy the `backend` to platforms like AWS EC2, Google Cloud Run, Heroku, or Vercel (for serverless functions if adapted).
- **Static Hosting**: Deploy the `frontend` web build to services like Netlify, Vercel, Firebase Hosting, or GitHub Pages.
- **Docker**: Create `Dockerfile`s for both frontend and backend for containerized deployment.
- **Mobile App Stores**: Distribute the `frontend` mobile builds through Google Play Store and Apple App Store.

## 📚 API Reference

The backend exposes a RESTful API to manage campus services, queues, and appointments.

### Base URL

`http://localhost:3005/api/v1`

### Authentication

All protected endpoints require a JSON Web Token (JWT) provided in the `Authorization` header as a Bearer token: `Authorization: Bearer <your_token>`.
